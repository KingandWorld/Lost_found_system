## 3. 第一步：环境搭建

### 3.1 宝塔面板安装基础环境

登录宝塔面板 → 软件商店，一键安装：

| 软件 | 版本 | 用途 |
|------|------|------|
| MySQL | 8.0 | 数据库 |
| Nginx | 1.22+ | Web 服务器 + 反向代理 |
| JDK | 17 | Java 运行环境（需手动安装或通过 Java 项目管理器） |

Ubuntu 系统手动安装 JDK 17：

```bash
apt update && apt install -y openjdk-17-jdk
java -version  # 验证安装
```

### 3.2 创建项目目录

```bash
mkdir -p /www/wwwroot/lost-found/{backend,frontend/dist,files/img}
```

目录结构：

```

├── backend/                ← Spring Boot JAR + 配置
│   ├── springboot-0.0.1-SNAPSHOT.jar
│   ├── application-prod.properties
│   └── startup.sh
├── frontend/dist/          ← Vue3 编译产物
│   ├── index.html
│   └── assets/
├── files/                  ← 用户上传文件存储
│   ├── img/
│   └── file/
```

## 5. 第三步：后端部署

### 5.1 配置文件

`application-prod.properties` 关键配置（完整文件见项目打包）：

```properties
server.port=1235
file.base-path=/www/wwwroot/lost-found/files
spring.datasource.url=jdbc:mysql://127.0.0.1:3306/lost_found_db?...
spring.datasource.password=YOUR_DB_PASSWORD

# ⚠️ JWT 密钥必须固定，不能每次启动随机生成
jwt.secret=${JWT_SECRET:固定密钥}
```

### 5.2 启动脚本

```bash
#!/bin/bash
# 关键：使用 spring.profiles.active 而非 spring.config.location
#       前者追加配置，后者完全替换（会导致 JAR 内部配置丢失）
java -jar springboot-0.0.1-SNAPSHOT.jar \
    --spring.profiles.active=prod
```

> ⚠️ **教训**：`--spring.config.location` 会**完全替换**默认配置路径，导致 JAR 内部的 `application.properties` 不被加载。必须使用 `--spring.profiles.active=prod` 来叠加外部配置。

### 5.3 设置权限

```bash
chmod -R 755 /www/wwwroot/lost-found/files
chown -R www:www /www/wwwroot/lost-found/files
```

## 6. 第四步：前端与 Nginx 部署

### 6.1 宝塔创建站点

网站 → 添加站点 → 根目录选 `/www/wwwroot/lost-found/frontend/dist`

### 6.2 Nginx 核心配置

```nginx
server {
    listen 80;
    server_name 你的域名或IP;
    root /www/wwwroot/lost-found/frontend/dist;

    # SPA History 模式
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:1235/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # ⚠️ 图片直接由 Nginx 提供（不经过后端）
    location ^~ /api/img/ {
        alias /www/wwwroot/lost-found/files/img/;
        expires 7d;
    }

    location ^~ /api/file/ {
        alias /www/wwwroot/lost-found/files/file/;
        expires 7d;
    }
}
```

## 7. 踩坑一：图片无法显示

### 现象

部署完成，功能正常，但所有物品的图片位置显示空白占位符。

### 排查过程

**第 1 步：确认文件存在**

```bash
ls /www/wwwroot/lost-found/files/img/
# 文件存在 ✅
```

**第 2 步：测试后端直接访问**

```bash
curl -I http://127.0.0.1:1235/api/img/1750670457832.png
# HTTP/1.1 200 ✅ 后端能正常提供图片
```

**第 3 步：测试 Nginx 代理访问**

```bash
curl -I http://localhost/api/img/1750670457832.png
# HTTP/1.1 404 ❌ Nginx 返回 404！
```

问题锁定：Nginx 配置有问题，请求没能正确路由。

## 8. 踩坑二：`^~` 修饰符失效

### 第一版配置（错误）

```nginx
location /img/ {
    alias /www/wwwroot/lost-found/files/img/;
}
```

### 为什么错误

Nginx location 匹配优先级：

```
1. =    (精确匹配)
2. ^~   (前缀匹配，停止正则搜索)  
3. ~ ~* (正则匹配)          ← 优先级高于普通前缀！
4.      (普通前缀匹配)
```

我的配置中还有一个嵌套在 `location /` 里的正则：

```nginx
location / {
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|...)$ {
        # 这个正则优先级 > 普通 location /img/
    }
}
```

当请求 `/img/photo.jpg` 命中这个正则时，Nginx 会用 `location /` 的 root（前端 dist 目录）去找图片，当然找不到。

### 修复

加上 `^~` 修饰符：

```nginx
location ^~ /img/ {   # ^~ 使优先级高于正则
    alias /www/wwwroot/lost-found/files/img/;
}
```

但问题依然存在！

## 9. 踩坑三：前端拼接 `/api` 前缀

### 再次排查

修改后图片仍不显示。用浏览器 F12 抓包，发现**没有一个失败的图片请求**——这意味着所有图片请求都返回了 200，但图片就是不出来？

再仔细看 Network 面板，图片请求的 URL 不是 `/img/xxx.jpg`，而是：

```
/api/img/xxx.jpg
```

### 根因

前端代码在所有图片路径前拼接了 `baseAPI`：

```javascript
// ItemList.vue:354
const baseAPI = import.meta.env.VITE_BASE_API || '/api'  // = '/api'

const getFirstImage = (images) => {
    const firstImage = images.split(',')[0]?.trim()  // '/img/xxx.jpg'
    return firstImage.startsWith('http') ? firstImage : baseAPI + firstImage
    //      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    //      结果：'/api/img/xxx.jpg'（不是 '/img/xxx.jpg'！）
}
```

所以实际请求是 `/api/img/xxx.jpg`，匹配的是 `location /api/` → 代理到后端 → 后端 Spring 资源映射。我配置的 `location ^~ /img/` 根本没被触发！

### 最终修复

在 `location /api/` **前面**增加 `location ^~ /api/img/`：

```nginx
# ⚠️ 必须放在 location /api/ 前面！
location ^~ /api/img/ {
    alias /www/wwwroot/lost-found/files/img/;
    expires 7d;
}

location ^~ /api/file/ {
    alias /www/wwwroot/lost-found/files/file/;
    expires 7d;
}

# API 代理放后面
location /api/ {
    proxy_pass http://127.0.0.1:1235/api/;
    ...
}
```

### 为什么需要四个 location

| Location | 处理场景 |
|----------|---------|
| `^~ /api/img/` | 前端拼接 `/api` 前缀的图片请求（最常见） |
| `^~ /api/file/` | 前端拼接 `/api` 前缀的文件请求 |
| `^~ /img/` | 直接访问图片（兜底） |
| `^~ /file/` | 直接访问文件（兜底） |

## 10. 踩坑四：定时任务自动过期

### 现象

图片终于显示了！但首页只显示了刚上传的 2 个新物品，数据库初始数据中的 5 个物品全部不显示。

### 排查

直接查数据库：

```sql
SELECT id, title, status FROM lost_item;
```

```
+----+----------------+--------+
| id | title          | status |
+----+----------------+--------+
|  1 | 丢失学生证     |      1 |
|  2 | 丢失黑色钱包   |      4 |   ← 不是 0！
|  3 | 学生证丢了     |      4 |
|  4 | 照片丢了       |      4 |
|  5 | test0000       |      2 |
|  6 | 新上传的物品   |      0 |   ← 只有这个显示
+----+----------------+--------+
```

### 根因

1. 后端有个 `@Scheduled` 定时任务 `ItemStatusTask`，每天凌晨 2 点执行
2. 它将超过 30 天的物品标记为 `EXPIRED`（status=4）
3. 数据库初始数据的日期是 **2025 年 6 月**，超过了 30 天
4. 后端启动后，定时任务立即触发，全部标记为过期

**状态对照表**：

| 值 | 含义 |
|----|------|
| 0 | 待认领（首页显示） |
| 1 | 已认领 |
| 2 | 已交接 |
| 3 | 已关闭 |
| 4 | 已过期 |

5. 前端首页 `Home.vue` 查询条件：

```javascript
request.get('/lost-item/page', {
    status: 0  // 只查待认领！
})
```

### 修复

```sql
-- 恢复过期物品
UPDATE lost_item SET status = 0 WHERE status = 4;
UPDATE found_item SET status = 0 WHERE status = 4;

-- 更新时间，防止再次被标记过期
UPDATE lost_item SET create_time = NOW(), update_time = NOW() WHERE status = 0;
UPDATE found_item SET create_time = NOW(), update_time = NOW() WHERE status = 0;
```

## 11. 最终配置

### 完整 Nginx 配置

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /www/wwwroot/lost-found/frontend/dist;
    index index.html;
    charset utf-8;

    # ========== 前端 SPA ==========
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ========== 图片/文件（必须在 /api/ 前面！）==========
    location ^~ /api/img/ {
        alias /www/wwwroot/lost-found/files/img/;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    location ^~ /api/file/ {
        alias /www/wwwroot/lost-found/files/file/;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    location ^~ /img/ {
        alias /www/wwwroot/lost-found/files/img/;
        expires 7d;
    }

    location ^~ /file/ {
        alias /www/wwwroot/lost-found/files/file/;
        expires 7d;
    }

    # ========== API 反向代理 ==========
    location /api/ {
        proxy_pass http://127.0.0.1:1235/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ========== 性能优化 ==========
    gzip on;
    gzip_comp_level 6;
    gzip_types text/css text/javascript application/javascript application/json;
}
```

### 启动脚本

```bash
#!/bin/bash
export JWT_SECRET="你的固定密钥"       # 必须固定！
export DB_PASSWORD="数据库密码"
export SPRING_SECURITY_PASSWORD="管理员密码"

java -Xms256m -Xmx512m \
    -jar springboot-0.0.1-SNAPSHOT.jar \
    --spring.profiles.active=prod       # 不是 --spring.config.location！
```

## 12. 总结

### 踩坑清单

| # | 问题 | 根因 | 教训 |
|---|------|------|------|
| 1 | 图片 404 | Nginx 图片路由未配置 | 部署前确认文件访问路径 |
| 2 | `^~` 无效 | 请求路径是 `/api/img/` 而非 `/img/` | 不要假设，用浏览器 F12 看实际请求 |
| 3 | `^~ /img/` 配了也没用 | 前端拼接了 `/api` 前缀 | 前后端路径约定要统一，或者 Nginx 全部覆盖 |
| 4 | 旧数据不显示 | 定时任务自动过期 + 前端过滤 status | 导入旧数据后要检查状态字段 |

### 核心经验

1. **浏览器 F12 是你的朋友**：Network 面板能告诉你真实请求路径，不要靠猜测
2. **`curl` 分层测试**：先测后端直连 → 再测 Nginx 代理 → 最后看浏览器
3. **Nginx location 优先级**：正则 `~` > 普通前缀，要拦截就用 `^~`
4. **Spring Boot 配置加载**：`--spring.profiles.active` 追加配置，`--spring.config.location` 完全替换
5. **检查定时任务**：项目导入旧数据后，注意有没有定时任务会修改状态
