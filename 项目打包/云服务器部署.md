## 2. 前期准备

### 2.1 所需信息

在开始部署前，请准备好以下信息：

| 项目 | 说明 | 示例 |
|------|------|------|
| 服务器 IP | 云服务器公网 IP | `123.456.789.0` |
| 域名（可选） | 已备案的域名 | `lost-found.example.com` |
| 宝塔面板地址 | 通常是 `https://IP:8888` | — |
| 宝塔用户名/密码 | 安装宝塔后生成 | — |
| MySQL root 密码 | 宝塔安装 MySQL 时设置 | — |

### 2.2 上传项目文件到服务器

使用宝塔面板的文件管理器上传文件：

1. **登录宝塔面板**：浏览器访问 `https://你的服务器IP:8888`

2. **进入文件管理**：点击左侧菜单「文件」

3. **创建项目目录**：
   - 在 `/www/wwwroot/` 下新建文件夹 `lost-found`
   - 在 `lost-found` 下创建三个子文件夹：
     - `backend`（存放后端 JAR 和配置）
     - `frontend`（存放前端静态文件）
     - `files`（存放用户上传的文件/图片）

   ```
   /www/wwwroot/lost-found/
   ├── backend/        ← 上传 backend 文件夹的所有内容
   ├── frontend/       ← 上传 frontend 文件夹的所有内容
   └── files/          ← 上传 uploads 内容（空目录标记）
   ```

4. **上传文件**：
   - 进入 `backend/` 目录，点击「上传」按钮，将本地 `项目打包/backend/` 下的 3 个文件全部上传
   - 进入 `frontend/` 目录，点击「上传」按钮，将本地 `项目打包/frontend/dist/` 下的 `index.html` 和 `assets/` 文件夹上传
   - 同时也上传 `nginx-config.conf` 到 `frontend/` 目录

   > 💡 **提示**：宝塔面板支持拖拽上传。如果文件夹上传失败，可以先在本地将 dist 文件夹压缩为 dist.zip，上传后在宝塔中解压。

## 3. 服务器环境安装

### 3.1 通过宝塔面板安装软件

宝塔面板的优势在于可以一键安装运行环境。请按以下步骤操作：

#### 步骤1：进入软件商店

登录宝塔面板 → 点击左侧「软件商店」

#### 步骤2：安装 MySQL 8.0

1. 在搜索框中输入「MySQL」
2. 找到 **MySQL 8.0**，点击「安装」
3. 安装方式选择「极速安装」
4. 安装过程中会提示设置 **root 密码**，请设置一个强密码并**牢记**
5. 等待安装完成（约 3-5 分钟）

#### 步骤3：安装 Nginx

1. 在搜索框中输入「Nginx」
2. 找到 **Nginx**（推荐 1.22 或更新版本），点击「安装」
3. 选择「极速安装」
4. 等待安装完成（约 1-2 分钟）

#### 步骤4：安装 Java 运行环境

1. 在搜索框中输入「Java」
2. 找到 **Java 项目管理器**（或 **Tomcat**，里面包含 JDK），点击「安装」

   > ⚠️ 注意：本项目使用 Spring Boot 3.2.0，需要 **JDK 17+**。如果宝塔面板的 Java 管理器默认版本较低，请按以下方式手动安装：

   **方式 A — 使用 Java 项目管理器（推荐）**：
   安装完成后，进入 Java 项目管理器 → JDK 管理 → 选择 JDK 17 安装。

   **方式 B — 手动安装 JDK 17**：
   如果面板中没有 JDK 17 选项，请通过 SSH 连接服务器手动安装：

   ```bash
   # SSH 连接服务器后执行
   # 安装 OpenJDK 17
   yum install -y java-17-openjdk java-17-openjdk-devel
   # 或者（Ubuntu/Debian 系统）
   # apt update && apt install -y openjdk-17-jdk

   # 验证安装
   java -version
   # 应输出：openjdk version "17.x.x" ...
   ```

### 3.2 验证环境安装

在宝塔面板 SSH 终端或通过 SSH 连接后执行：

```bash
# 检查 Java
java -version

# 检查 MySQL
systemctl status mysqld
# 或
/etc/init.d/mysqld status

# 检查 Nginx
nginx -v
systemctl status nginx
```

#### 方式一：通过宝塔面板导入（推荐）

1. 点击左侧「数据库」菜单

## 5. 后端部署

### 5.1 配置文件修改

在部署后端之前，**必须先修改配置文件中的敏感信息**：

在宝塔文件管理中，进入 `/www/wwwroot/lost-found/backend/` 目录，
找到 `application-prod.properties` 文件，点击文件名进行编辑：

```properties
# ========== 以下三项必须修改 ==========

# 1. 数据库密码 — 改为你在宝塔中为 lost_found_user 设置的密码
spring.datasource.password=YOUR_DB_PASSWORD_HERE

# 2. JWT 密钥 — 使用 openssl rand -base64 48 生成的新密钥替换
#    （SSH 连接服务器后执行 openssl rand -base64 48 获取随机密钥）
jwt.secret=CHANGE_ME_GENERATE_RANDOM_48_CHAR_KEY

# 3. Spring Security 密码 — 设置管理员密码
spring.security.user.password=${SPRING_SECURITY_PASSWORD:Admin@123!}
```

> ⚠️ **安全警告**：绝对不要使用默认密码！以上三项必须修改为生产环境的强密码。

### 5.2 修改启动脚本

编辑 `startup.sh`，**必须修改以下所有密码和密钥**：

```bash
# ⚠️ 以下四项必须修改，不要使用默认值！

# 1. JWT_SECRET — 必须是固定值！每次启动都变化会导致所有用户 token 失效
#    在 SSH 中执行 openssl rand -base64 48 生成一个随机密钥填入
export JWT_SECRET="CHANGE_ME_GENERATE_WITH_openssl_rand_base64_48"

# 2. 数据库密码
export DB_PASSWORD="你的数据库密码"

# 3. Spring Security 管理员密码
export SPRING_SECURITY_PASSWORD="你的管理员强密码"

# 4. 新用户默认密码
export USER_DEFAULT_PASSWORD="你的新用户默认密码"

# 5. Knife4j 文档密码（生产环境已关闭文档，可选改）
export KNIFE4J_PASSWORD="API文档访问密码"
```

### 5.3 设置文件权限

SSH 连接服务器，执行以下命令：

```bash
# 进入项目目录
cd /www/wwwroot/lost-found/backend

# 赋予启动脚本执行权限
chmod +x startup.sh

# 创建日志目录
mkdir -p logs

# 设置 files 目录权限（确保后端可写入上传文件）
chmod -R 755 /www/wwwroot/lost-found/files
chown -R www:www /www/wwwroot/lost-found/files
```

### 5.4 测试启动后端

```bash
cd /www/wwwroot/lost-found/backend

# 启动
bash startup.sh start

# 查看状态
bash startup.sh status

# 查看日志
tail -f logs/lost-found-system.log
```

看到类似以下日志表示启动成功：
```
Started SpringbootApplication in 8.xxx seconds
```

### 5.5 验证后端运行

在服务器上执行：
```bash
curl http://localhost:1235/api/lost-item/statistics
```

如果返回 JSON 数据，说明后端运行正常。

### 5.6 设置后端开机自启（宝塔面板）

1. 点击左侧「Java 项目管理器」（如果未安装请先安装）
2. 点击「添加 Java 项目」
3. 填写：

   | 字段 | 值 |
   |------|-----|
   | 项目名称 | `失物招领系统` |
   | JDK 版本 | JDK 17 |
   | JAR 路径 | `/www/wwwroot/lost-found/backend/springboot-0.0.1-SNAPSHOT.jar` |
   | 运行参数 | `--spring.profiles.active=prod` |
   | 端口 | `1235` |

4. 点击「提交」
5. 在项目列表中找到刚添加的项目，点击「启动」
6. 开启「开机自启」开关

> 如果需要手动管理（不使用 Java 项目管理器），可以添加 systemd 服务或使用宝塔的「计划任务」实现开机启动。

## 7. Nginx 配置

### 7.1 打开 Nginx 配置

1. 点击左侧「网站」菜单
2. 找到刚才创建的站点，点击右侧的「设置」
3. 点击「配置文件」选项卡

### 7.2 替换配置内容

将 `项目打包/frontend/nginx-config.conf` 的内容复制进去，并**修改以下两处**：

1. `server_name` — 改为你的实际域名或 IP
2. `root` — 改为实际前端文件路径（通常不用改）

**关键配置说明**：

```nginx
# 前端 SPA 路由 — Vue Router history 模式必须配置
location / {
    try_files $uri $uri/ /index.html;
}

# API 反向代理 — 前端请求 /api/xxx 会转发到后端 1235 端口
location /api/ {
    proxy_pass http://127.0.0.1:1235/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

# ⚠️ 图片/文件由 Nginx 直接从文件系统提供（不经过后端，性能更好）
# 路径必须与 application-prod.properties 中 file.base-path 一致
# ⚠️ 关键：前端在图片路径前拼接了 /api 前缀（baseAPI + imagePath），
#   实际请求是 /api/img/xxx.jpg，所以两套路径都需要配置！
# ⚠️ 必须放在 location /api/ 前面，^~ 确保不被 /api/ 拦截
location ^~ /api/img/ {
    alias /www/wwwroot/lost-found/files/img/;
    expires 7d;
    add_header Cache-Control "public, immutable";
}

location ^~ /api/file/ {
    alias /www/wwwroot/lost-found/files/file/;
    expires 7d;
    add_header Cache-Control "public, immutable";
}

location ^~ /img/ {
    alias /www/wwwroot/lost-found/files/img/;
    expires 7d;
    add_header Cache-Control "public, immutable";
}

location ^~ /file/ {
    alias /www/wwwroot/lost-found/files/file/;
    expires 7d;
    add_header Cache-Control "public, immutable";
}
```

> ⚠️ **重要**：`/img/` 和 `/file/` 使用 `alias` 直接从文件系统读取上传的文件，**不经过后端代理**。如果 `file.base-path` 修改过，这里的 `alias` 路径也需要同步修改。

### 7.3 保存并重载 Nginx

1. 编辑完配置文件后，点击「保存」
2. 宝塔会自动检测配置语法，如有错误会提示
3. 回到「网站」列表，点击站点的「重载」按钮（或重启 Nginx）

或者在 SSH 中执行：
```bash
nginx -t                    # 测试配置语法
nginx -s reload             # 重载配置
```

### 7.4 配置 SSL/HTTPS（推荐）

如果你有域名，强烈建议开启 HTTPS：

1. 在站点「设置」→「SSL」选项卡
2. 选择「Let's Encrypt」（宝塔面板内置支持，免费）
3. 勾选你的域名
4. 点击「申请」
5. 申请成功后，开启「强制 HTTPS」

> 开启 HTTPS 后，记得在部署文档中更新 API 地址为 `https://`。

### 8.4 验证图片显示

**这是部署中最常见的遗漏项**，请务必单独验证：

1. **上传初始图片（重要！）**：
   数据库中初始数据引用了 19 张图片，这些图片存在于 `项目打包/uploads/` 目录中。
   **必须将这些图片上传到服务器** `/www/wwwroot/lost-found/files/img/` 目录：
   - 宝塔面板 → 文件 → 进入 `/www/wwwroot/lost-found/files/img/`
   - 将 `项目打包/uploads/` 下的 19 张图片全部上传到该目录

2. **确认上传目录存在并拥有正确权限**：
   ```bash
   # 创建 img 子目录（如果不存在）
   mkdir -p /www/wwwroot/lost-found/files/img
   # 设置权限（Nginx 用户 www 需要读取权限）
   chmod -R 755 /www/wwwroot/lost-found/files
   chown -R www:www /www/wwwroot/lost-found/files
   ```

3. **直接测试图片 URL**：
   在浏览器中访问一个已知的图片路径：
   ```
   http://你的域名/api/img/1747189926597.jpg
   ```
   如果返回图片（不是 404），说明 Nginx 配置正确。

4. **检查 Nginx 是否成功重载**：
   ```bash
   nginx -t && nginx -s reload
   ```

5. **查看 Nginx 错误日志**（如果图片 404）：
   ```bash
   tail -50 /www/wwwlogs/你的域名.error.log
   ```

### 8.5 宝塔面板安全组/防火墙设置

确保服务器的安全组（云服务商控制台）和防火墙已放行以下端口：

| 端口 | 用途 | 是否必须对外 |
|------|------|-------------|
| 80 | HTTP（Nginx） | ✅ 是 |
| 443 | HTTPS（Nginx） | ✅ 是（如果开启 SSL） |
| 8888 | 宝塔面板 | ⚠️ 建议仅限特定 IP |
| 1235 | 后端 API | ❌ 否（仅 Nginx 内部访问） |
| 3306 | MySQL | ❌ 否（仅本地访问） |

**宝塔面板中设置防火墙**：
1. 点击左侧「安全」
2. 确认 80、443 端口已放行
3. **建议删除** 3306 端口的放行规则（防止数据库被外网攻击）
4. **建议修改** 8888 端口为仅特定 IP 可访问，或修改宝塔面板默认端口

## 9. 常见问题排查

### 9.1 前端页面 404 或刷新后 404

**原因**：Vue Router 使用 History 模式，Nginx 未正确配置 `try_files`。

**解决**：检查 Nginx 配置中是否有：
```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```
修改后执行 `nginx -s reload`。

### 9.2 前端请求 API 返回 404

**原因**：Nginx 反向代理未配置或配置错误。

**排查步骤**：
1. 浏览器 F12 → Network 标签 → 查看 API 请求的实际 URL
2. 确认请求 URL 是以 `/api/` 开头
3. 检查 Nginx 中 `/api/` 的 proxy_pass 配置
4. 确认后端是否在 1235 端口运行：`netstat -tlnp | grep 1235`

### 9.2.1 图片无法显示（上传的图片返回 404）⚠️ 高频问题

这是部署后最常见的问题。图片上传成功但前端不显示，通常有以下原因：

**原因 A — 缺少 /api/img/ 的 location 配置（最最常见！）**：
前端代码 `getFirstImage()` 会在图片路径前拼接 `baseAPI`（即 `/api`），所以实际请求是 `/api/img/xxx.jpg`，**不是** `/img/xxx.jpg`。Nginx 的 `location /api/` 会将其代理到后端，如果后端资源映射也有问题就显示不了。解决方案是在 `location /api/` **前面**增加 `location ^~ /api/img/` 直接读取文件系统。

**原因 B — files 目录权限不足**：
Nginx 用户（通常是 `www`）没有读取 `/www/wwwroot/lost-found/files/` 的权限。

**原因 C — files/img 目录不存在**：
只有 `files/` 目录但没有 `files/img/` 子目录。

**原因 D — 后端 file.base-path 与实际路径不一致**：
`application-prod.properties` 中 `file.base-path` 指向的路径与 Nginx `alias` 路径不匹配。

**排查步骤（请按顺序操作）**：

1. **确认 Nginx 配置正确（最关键的一步）**：
   ```bash
   # 查看 Nginx 配置中 img 相关部分
   cat /www/server/panel/vhost/nginx/*.conf | grep -B1 -A4 "img"
   ```
   正确配置必须包含 **4 个 location**（缺一不可）：
   ```nginx
   # ✅ 处理带 /api 前缀的请求（前端 baseAPI + imagePath，最常见）
   location ^~ /api/img/ {
       alias /www/wwwroot/lost-found/files/img/;
   }
   location ^~ /api/file/ {
       alias /www/wwwroot/lost-found/files/file/;
   }
   # ✅ 处理不带 /api 前缀的请求（兜底）
   location ^~ /img/ {
       alias /www/wwwroot/lost-found/files/img/;
   }
   location ^~ /file/ {
       alias /www/wwwroot/lost-found/files/file/;
   }
   ```
   **缺少 `/api/img/` 是图片不显示的最常见原因**。前端在图片路径前拼接了 `/api`，实际请求是 `/api/img/xxx.jpg`，只配 `/img/` 无法命中。
   **`^~` 修饰符**确保不被 `location /api/` 或 `location ~* \.(jpg|...)$` 拦截。

2. **确认目录和权限**：
   ```bash
   # 创建 img 子目录
   mkdir -p /www/wwwroot/lost-found/files/img
   # 设置权限
   chmod -R 755 /www/wwwroot/lost-found/files
   chown -R www:www /www/wwwroot/lost-found/files
   # 验证 Nginx 用户可以访问
   sudo -u www ls /www/wwwroot/lost-found/files/img/
   ```

3. **直接测试图片 URL**：
   在浏览器中访问：
   ```
   http://你的域名/img/任意文件名.jpg
   ```
   如果返回 404，查看 Nginx 错误日志：
   ```bash
   tail -50 /www/wwwlogs/你的域名.error.log
   ```
   日志中会明确显示 Nginx 尝试从哪个路径读取文件，对比这个路径与实际文件路径是否一致。

4. **验证后端文件上传路径**：
   检查后端启动日志中「文件存储根目录已配置」这行的输出：
   ```bash
   grep "文件存储根目录" /www/wwwroot/lost-found/backend/logs/lost-found-system.log
   ```
   确认这个路径与 Nginx `alias` 路径一致。

5. **临时验证：通过后端访问图片**：
   ```bash
   # 后端也有 /img/ 资源映射，可用于验证文件是否确实存在
   curl -I http://localhost:1235/img/某文件名.jpg
   ```
   如果返回 200，说明文件存在于后端的 `file.base-path` 目录中，问题在 Nginx。

6. **应用修复后重载 Nginx**：
   ```bash
   nginx -t && nginx -s reload
   ```

### 9.3 后端启动失败

**常见原因**：

| 症状 | 可能原因 | 解决 |
|------|---------|------|
| `Connection refused` | MySQL 未运行 | `systemctl start mysqld` |
| `Access denied for user` | 数据库密码错误 | 检查 `application-prod.properties` 中的密码 |
| `Unknown database` | 数据库未创建或名称不对 | 检查数据库名是否为 `lost_found_db` |
| `port 1235 already in use` | 端口被占用 | `lsof -i :1235` 查看并 kill 占用进程 |
| `Unsupported class version` | JDK 版本不对 | 确认使用 JDK 17（`java -version`） |

### 9.4 文件上传失败

**原因**：文件存储目录不存在或权限不足。

**解决**：
```bash
mkdir -p /www/wwwroot/lost-found/files
chmod -R 755 /www/wwwroot/lost-found/files
chown -R www:www /www/wwwroot/lost-found/files
```
同时检查 `application-prod.properties` 中 `file.base-path` 配置是否正确。

### 9.5 登录后 token 失效或认证失败

**原因**：JWT 密钥与之前不一致（重启后密钥变更）。

**解决**：
1. 在 `application-prod.properties` 中固定 `jwt.secret` 值，不要每次启动随机生成
2. 修改配置后重启后端
3. 用户需要重新登录

### 9.6 宝塔面板无法访问

**原因**：防火墙未放行面板端口或面板服务未启动。

**解决**：
```bash
# 检查面板状态
bt status

# 启动面板
bt start

# 检查防火墙
firewall-cmd --list-ports
# 或
ufw status

# 放行端口（CentOS）
firewall-cmd --zone=public --add-port=8888/tcp --permanent
firewall-cmd --reload
```

### 9.7 常用排查命令

```bash
# 查看后端日志
tail -100 /www/wwwroot/lost-found/backend/logs/lost-found-system.log

# 查看 Nginx 错误日志
tail -100 /www/wwwlogs/nginx-error.log

# 查看 Nginx 访问日志
tail -100 /www/wwwlogs/nginx-access.log

# 检查端口占用
netstat -tlnp | grep -E "80|443|1235|3306"

# 检查进程
ps aux | grep java
ps aux | grep nginx
ps aux | grep mysql

# 重启服务
systemctl restart nginx
systemctl restart mysqld
```
