# 失物招领系统 — API 自动化测试

本目录包含对失物招领系统后端 REST API 的自动化测试脚本，
覆盖全部业务模块：用户、分类、失物、招领、认领申请、通知。

---

## 📋 测试文件说明

| 文件 | 说明 | 依赖 |
|------|------|------|
| `api_test.py` | Python 全功能测试脚本（推荐） | Python 3.6+, `requests` 库 |
| `test_runner.sh` | curl 快速测试脚本（轻量） | bash, curl, python3 |
| `lost_found_api_test.postman_collection.json` | Postman 集合（可视化） | Postman 桌面版 |

---

## 🚀 快速开始

### 前置条件

1. **启动后端服务**（端口 1235）
2. **初始化数据库**（MySQL 已运行，`lost_found_db` 已导入）

### 方式一：Python 测试（推荐）

```bash
# 安装依赖
pip install requests

# 运行全部测试
python api_test.py

# 指定服务器地址
python api_test.py --base-url http://localhost:1235

# 使用不同的测试账号
python api_test.py --admin-user admin --admin-pass 123456
```

### 方式二：curl 脚本测试

```bash
# 运行快速测试
bash test_runner.sh

# 指定服务器地址
bash test_runner.sh http://localhost:1235
```

### 方式三：Postman 测试

1. 打开 Postman → **Import** → 选择 `lost_found_api_test.postman_collection.json`
2. （可选）创建环境，设置 `base_url` = `http://localhost:1235`
3. 按文件夹顺序执行：
   - 先执行「用户管理」中的登录请求获取 token
   - 后续请求会自动使用环境变量中的 token

## 🔧 常见问题

**Q: 提示连接被拒绝（Connection refused）**
A: 确认后端已启动：`curl http://localhost:1235/api/lost-item/page`

**Q: Python 脚本中 token 为空**
A: 确认数据库中的用户密码为 `123456`（默认），或使用 `--admin-pass` 参数指定

**Q: 部分测试失败**
A: 有些测试依赖特定的数据库状态（如认领申请 ID），如果数据已被操作可能会失败，
  这属于正常情况，可查看具体错误消息判断是否由数据状态引起

**Q: Windows 下运行 test_runner.sh**
A: 使用 Git Bash 或 WSL 运行。或手动执行其中的 curl 命令
